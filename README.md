# Дом культуры — сайт

Пересборка сайта бара и площадки событий [d-k.bar](https://d-k.bar)
(Екатеринбург, Бажова, 193).

Статический сайт на [Astro](https://astro.build). Сборка выдаёт обычные
HTML-файлы: их можно положить на любой хостинг, никакого сервера и базы
данных не нужно.

---

## Быстрый старт

```bash
npm install
npm run dev      # локальная разработка, http://localhost:4321
npm run build    # сборка в dist/
npm test         # контраст + сборка + проверки собранного сайта
```

| Команда | Что делает |
| --- | --- |
| `npm run dev` | Локальный сервер с горячей перезагрузкой |
| `npm run build` | Пересобирает превью-картинки и весь сайт в `dist/` |
| `npm run preview` | Показывает то, что собралось |
| `npm run check` | Проверка типов и разметки |
| `npm run contrast` | Контраст палитры по WCAG 2.2 |
| `npm run verify` | Проверки собранного сайта: заголовки, alt, ориентиры, JSON-LD, canonical, битые ссылки и якоря, вес страниц |
| `npm test` | Всё перечисленное разом |

Публиковать нужно содержимое папки `dist/`.

## Что где лежит

```
src/
├─ data/site.ts          ← адрес, телефон, часы, ссылки. Единственный источник правды
├─ content/
│  ├─ events/*.md        ← афиша: один файл = одно событие
│  └─ menu/*.md          ← меню: один файл = один раздел
├─ content.config.ts     ← правила заполнения (что обязательно, что нет)
├─ assets/               ← исходные фото и постеры (оптимизируются при сборке)
├─ components/           ← кирпичики интерфейса
├─ layouts/              ← общая оболочка страниц
├─ pages/                ← страницы; путь файла = адрес на сайте
├─ lib/                  ← даты по-русски, навигация
└─ styles/               ← токены дизайна и базовые стили
scripts/
├─ generate-og.mjs       ← превью для соцсетей и иконки приложения
├─ build-menu.mjs        ← разовый перенос меню из сканов (см. ниже)
├─ verify.mjs            ← проверки собранного сайта
└─ contrast.mjs          ← проверка контраста палитры
```

## Как добавить событие в афишу

Создайте файл в `src/content/events/`. Имя файла станет адресом страницы:
`kvartirnik-oktyabr.md` → `/afisha/kvartirnik-oktyabr`.

```markdown
---
title: "Квартирник: Иванов и друзья"
startsAt: 2026-10-12T20:00:00+05:00   # обязательно с поясом +05:00 (Екатеринбург)
kind: квартирник                       # см. список ниже
venue: "Основной зал"                  # или "Летняя веранда", "Весь дом"
summary: "Акустический вечер на малой сцене."
lineup:
  - "Иванов"
poster: ./../../assets/events/kvartirnik-oktyabr.jpg
posterAlt: "Афиша квартирника Иванова в Доме культуры"
price: "500 ₽"                         # или free: true
ticketUrl: "https://t.me/domcultekb123"
ticketLabel: "Забронировать стол"
---

Пара абзацев про вечер: кто играет, что будет, как одеться.
```

Положите постер в `src/assets/events/` — сжатие, webp и все размеры
сделает сборка. Исходник лучше грузить крупным, 1500–2000 px по стороне.

**Допустимые значения `kind`:** концерт, dj-сет, вечеринка, театр,
перформанс, стендап, мастер-класс, фестиваль, гастроужин, квартирник, музлото.

Событие с `draft: true` не попадёт на сайт. Если дата ещё не назначена —
`dateTba: true` вместо `startsAt`.

Прошедшие события **не нужно удалять**: они сами уезжают в раздел
«Прошедшие события» на странице афиши. Событие считается актуальным
ещё восемь часов после начала — чтобы ночной концерт не исчезал
с афиши посреди самого концерта.

## Как поправить меню

Каждый раздел меню — файл в `src/content/menu/`:

```markdown
---
title: "Культурные коктейли"
card: bar               # bar | kitchen | banquet
group: "Коктейли"       # вкладка внутри карты
order: 10               # чем меньше, тем выше
note: "Выход коктейля указан с учётом льда"
items:
  - name: "Морской гимлет"
    description: "Джин на вакаме, кордиал саган дайля, пена из игристого"
    measure: "120"
    price: 720
---
```

`price` — число, без «₽» и пробелов: из него считается диапазон цен
в описании страницы и собирается микроразметка для поисковиков.

## Что нужно сделать заведению

Ниже — то, что нельзя было закрыть на стороне разработки. Это не
пожелания, а вещи, без которых часть сайта остаётся неточной.

### Обязательно перед публикацией

1. **Подтвердить график работы.** На старом сайте он указан по-разному
   в шапке (вс 18:00–02:00, пт-сб 18:00–06:00) и в подвале
   (пн-чт 17:00–02:00, пт 17:00–06:00, сб 12:00–06:00, вс 12:00–02:00).
   Взят вариант из подвала — `src/data/site.ts`, поле `hours`.

2. **Разобраться с ценами на напитки.** На старом сайте одновременно
   выложены две версии страницы чая, кофе и лимонадов с разными ценами:
   эспрессо 270 и 250 ₽, авторский чай 470 и 540 ₽. За основу взята
   более поздняя версия (файл `__2026_page-0004.jpg`), но это нужно
   подтвердить. Разделы: `bar-kofe.md`, `bar-avtorskiy-chay.md`,
   `bar-napitki.md`, `bar-limonady.md`, `bar-zelenyy-chay.md`,
   `bar-chernyy-chay.md`, `bar-tizany.md`.

3. **Вписать реквизиты оператора персональных данных** в
   `src/pages/pravovaya-informatsiya.astro` — константа
   `OPERATOR_PLACEHOLDER`. Наименование, ИНН, ОГРН, юридический адрес.
   Придумывать их за вас нельзя, а без них правовые страницы
   не имеют силы.

4. **Проверить меню против кассы.** 292 позиции перенесены из сканов
   распознаванием, ещё 22 (конструкторы бранчей) — вручную. Всего
   на сайте 314 позиций: 266 в основном меню и 48 в банкетном.
   Ошибки возможны, особенно в длинных составах банкетного меню,
   где часть строк на скане обрезана.

5. **Обновить афишу.** На момент пересборки в ней одно предстоящее
   событие из восьми — остальные уже прошли.

### Стоит сделать

6. **Написать описания событий.** Все восемь карточек на старом сайте
   содержали заглушку «Описание, состав музыкантов». В новых файлах
   стоит `copyPending: true` и комментарий `TODO` — по нему их легко найти.

7. **Заказать фотосъёмку.** Со старого сайта удалось забрать всего три
   фотографии на весь сайт. Это главный дефицит: нужны зал, веранда,
   сцена во время события, бар за работой, ключевые блюда и коктейли.

8. **Прислать векторный логотип.** Сейчас используется растровый
   оригинал, снятый с материалов заведения (1840×629). Вектор от
   дизайнера даст идеальную резкость на любых размерах.

9. **Свести реферальные коды карты лояльности.** На старом сайте их два
   (`ref=vdfk6424` в шапке и `ref=bajt9427` в остальных местах) —
   статистика привлечения делится пополам. Оставлен `bajt9427`.

10. **Проверить разделение Telegram-адресов.** Бронь ведёт в
   `@domcultekb123` (аккаунт администратора), анонсы — в канал
   `@domcultekb`. На старом сайте они использовались вперемешку.

## Что даст следующий прирост

По убыванию отдачи. Первые три — то, что сейчас теряет заявки.

1. **Заполнить афишу.** Полупустая афиша обнуляет всё остальное:
   она сообщает «здесь ничего не происходит». Держите 6–8 будущих дат.
   Сейчас предстоящее событие одно.

2. **Написать условия входа цифрами.** Депозит на столы у сцены,
   сколько держим бронь при опоздании, можно ли прийти без брони.
   Сейчас на карточках стоит честное «уточним при брони» — но человек,
   который не может прикинуть вечер в деньгах, чаще не идёт вовсе.

3. **Снять фотографии.** Три кадра на весь сайт — главный дефицит.
   Нужны: зал в вечер концерта с людьми, веранда, хиты кухни и бара.
   По текущим фото невозможно понять формат: тихий ресторан
   или бар с танцполом до шести утра.

4. **Описания событий.** «Вечер сценического перформанса в основном
   зале» не объясняет, что человек увидит, и такую карточку
   не пересылают друзьям — а именно пересылка приводит компании.
   Нужно: кто выступает, что происходит, для кого.

5. **Составы блюд в основном меню.** В банкетном они есть, в основном
   почти нет: гость не понимает, за что 850 ₽. Данные уже собраны —
   нужно только дописать.

6. **Заявка должна доходить до вас даже незавершённой.** Сейчас форма
   складывает сообщение и открывает Telegram: если человек не дожал
   последний шаг, заявки не существует. Починить можно только сервером
   или ботом — статический сайт этого не умеет. Решается за вечер,
   если нужно.

7. **Аналитика.** Ни одну из проблем выше нельзя оценить в деньгах,
   пока не видно, сколько людей доходит до брони. См. раздел
   «Чего на сайте намеренно нет».

## Решения, которые стоит знать

**Меню перестало быть картинками.** Раньше это были 25 растровых
сканов общим весом 4,7 МБ: их нельзя было прочитать скринридером,
найти поиском, увеличить на телефоне (исходники 420×1100 px) или
проиндексировать. Теперь меню — текст: 266 позиций, первая загрузка
страницы 76 КБ, поиск по названиям и составам, микроразметка
`Menu` с ценами для поисковиков.

**У каждого события появился свой адрес.** Раньше афиша жила внутри
JS-попапа без собственных URL. Теперь `/afisha/senlima` можно
отправить в чат, а поисковик видит `Event` с датой, местом
и координатами.

**Палитра выведена из носителей бренда, а не придумана.** Латунь —
с вывески, глубокая зелень и охра — с интерьерных снимков, красный —
из печатного меню. Тёмная основа примиряет все три источника; красный
оставлен только для срочного («сегодня»), потому что в печати он
работает на белом, а на тёмном фоне спорит с латунью.

**Шрифты лежат на своём домене.** Google Fonts в России нестабилен,
а шрифт в критическом пути отрисовки. Кириллические подмножества
Unbounded и Manrope весят 46 КБ и предзагружаются.

**Карта грузится по клику.** Виджет Яндекс Карт — сторонний сервис
со своими cookie. Пока гость не нажал «Показать карту», запросов
к Яндексу не уходит.

**Бронь собирает заявку заранее.** Форма на странице контактов
складывает дату, время, число гостей и имя в готовое сообщение и
копирует его — в чат уходит заявка, а не «здравствуйте». Данные
никуда не отправляются с сайта: гость отправляет их сам, из своего
Telegram. Телефон остаётся равноправным путём.

**Всё работает без JavaScript.** Фильтры афиши и поиск по меню —
надстройка: без скриптов виден весь контент, просто без фильтрации.

**Проверки — часть сборки, а не обещание.** `npm test` прогоняет
контраст палитры по WCAG, собирает сайт и проверяет результат:
по одному h1 на страницу, alt у каждой картинки, ориентиры и
«пропустить к содержанию», валидный JSON-LD с обязательными полями,
canonical, совпадающий с sitemap, отсутствие битых внутренних ссылок
и якорей, отсутствие внутренних комментариев в продакшн-разметке
и вес первой загрузки каждой страницы. Всё это ставится в CI
на каждый пул-реквест через `netlify.toml`.

## Перенос меню из сканов

`scripts/build-menu.mjs` — разовый скрипт миграции. Он читает результат
распознавания печатных полос и раскладывает его по файлам
`src/content/menu/`. Повторно запускать его нужно только если
понадобится переснять миграцию с нуля:

```bash
node scripts/build-menu.mjs <путь-к-extract.json>
```

Файлы `brunch-*.md` он не трогает: конструкторы бранчей перенесены
вручную, потому что там цена складывается из основы и начинки.

Примечания разделов (`note:`) скрипт берёт не из распознавания,
а из списка `NOTES` внутри себя. Распознавание складывало туда
описания печатной вёрстки («Шапка колонок над списком: „ГР.“ и
„ЦЕНА“ красным мелким капсом») — для миграции полезно,
для посетителя мусор.

**Повседневные правки меню делаются прямо в `src/content/menu/*.md`,
скрипт для этого не нужен.**

## Витрина для заказчика

Сайт выложен на GitHub Pages, чтобы его можно было показать без
установки чего-либо:

**https://yaroalav75190-lang.github.io/dom-kultury/**

Обновляется сам: любой `git push` в `main` пересобирает и выкладывает
страницу (`.github/workflows/pages.yml`).

Это **предпросмотр, а не боевой сайт**. Он собирается в подпапку
и помечен `noindex`, чтобы копия не конкурировала с d-k.bar в поиске
и не растаскивала позиции. Боевая сборка (`npm run build` без
переменных) по-прежнему настроена на корень d-k.bar и индексируется.

Собрать такую же копию локально:

```bash
PAGES_SITE=https://example.github.io PAGES_BASE=имя-подпапки PUBLIC_PREVIEW=true npm run build
```

## Логотип

**Логотип нельзя перерисовывать, набирать шрифтом или заменять
похожим.** Везде используется оригинальное начертание из
`src/assets/brand/logotype.png` — тот же файл, что и в фирменных
носителях заведения.

Компонент `src/components/Logo.astro` подставляет этот файл CSS-маской,
а цвет берёт из `currentColor`. Так один и тот же рисунок работает
латунным в шапке и любым другим там, где понадобится, — форма букв
при этом не меняется вовсе.

Иконки и превью для соцсетей собираются из него же скриптом
`scripts/generate-og.mjs`: он перекрашивает логотип через альфа-канал.
Для мелких иконок берётся вырезка литеры «Д» из оригинала —
полная надпись в 32 пикселя нечитаема.

Если у заведения найдётся векторный исходник логотипа, его стоит
положить вместо растрового: качество вырастет, логика не изменится.

## Публикация

Сборка кладёт готовые файлы в `dist/`. Дальше — любой статический
хостинг: Netlify, Vercel, Cloudflare Pages, обычный nginx.

Настройка уже лежит в репозитории:

| Файл | Что задаёт |
| --- | --- |
| `netlify.toml` | Команда сборки, версия Node, редирект с `www`, прогон тестов на каждом пул-реквесте |
| `public/_headers` | Кеширование, заголовки безопасности, CSP. Понимают Netlify и Cloudflare Pages |
| `public/_redirects` | Переадресация старых адресов Tilda `/tproduct/*` в афишу |

**На nginx или Apache** эти правила нужно перенести руками —
файлы `_headers` и `_redirects` там не работают.

Что нужно проверить после первой публикации:

- **Редирект с http на https.** На старом сайте `http://` отдавал 200
  без редиректа, а canonical указывал на незащищённую версию —
  это дубль в индексе. Большинство хостингов делают такой редирект
  сами, но проверить стоит.
- **Страница 404** должна отдаваться с кодом 404, а не 200.
- **Sitemap** отправить в Яндекс Вебмастер и Google Search Console:
  `https://d-k.bar/sitemap-index.xml`.

Домен и адрес сайта заданы в `astro.config.mjs` (`site`) и
`src/data/site.ts`. Часовой пояс — `src/lib/datetime.ts`.

### Чего на сайте намеренно нет

**Аналитики.** На старом сайте её тоже не было. Ставить Яндекс Метрику
или что-то подобное — решение владельца: это сторонний сервис,
собирающий данные посетителей, и его нужно отразить в политике
конфиденциальности. Технически добавляется одним скриптом в
`src/layouts/BaseLayout.astro`; не забудьте разрешить его домен
в `Content-Security-Policy` в `public/_headers`.
